Chapter 17: String Detect

Text Searches and Data Filtering

Overview

Many datasets include text, such as movie titles, country names, and survey answers. In this chapter, you will use str_detect() to find text that matches a pattern and combine those results with dplyr::filter() to select rows. You will also search passages from a research-integrity article, count matching passages, and retrieve them to read in context.

By the end of Chapter 17 you will be able to:

  • 🔍 Find matching text in row names and character columns with str_detect().

  • 🎯 Use word boundaries, alternation, and capitalization options to define a search pattern.

  • 🧺 Combine text-matching results with filter() to select rows.

  • 🔁 Use sapply() and lapply() to apply an operation to several objects or keywords.

  • 📖 Build a keyword index, retrieve matching passages, and distinguish passage counts from word-occurrence counts.

Keep these goals in mind as you move through each section.

Warm‑Up

What is str_detect()?

A pattern describes what you want to find in text. The string argument supplies the text to search, and pattern supplies the matching rule.

📜 The SYNTAX: str_detect(string, pattern, negate = FALSE)

🎯 Goal: Use the help file to identify the arguments and the type of result returned.

?str_detect    # Arguments and return value (logical)

🗣 Comment: What do the string and pattern arguments supply, and what type of result does the function return?

For each nonmissing text value, str_detect() returns TRUE if the pattern matches and FALSE otherwise. You can use those logical results to filter rows or find matching positions.

Row‑name search

🎯 Goal: Find states whose names begin with New.

View(USArrests)  # View USArrests dataset in RStudio viewer
row.names(USArrests)  # Check row names of USArrests dataset
# ⚡ Code
New_states <- USArrests %>%
  filter(str_detect(row.names(USArrests), "^New"))

The ^ anchors the pattern to the beginning of each name. The assignment saves the selected rows as New_states.

✔️ In Chapter 11, a comparison such as mpg >= 25 returned logical results. Here, str_detect() tests text instead of comparing numbers. filter() still uses the results in the same way: it keeps rows where the test returns TRUE.

# ✅ Check
row.names(New_states)
[1] "New Hampshire" "New Jersey"    "New Mexico"    "New York"

🗣 Comment: Which New states were found?

Column search

The movielens data frame contains one row per rating, so a movie title can appear in many rows.

🎯 Goal: Keep rating rows whose movie title contains the whole word Love.

View(movielens)
nrow(movielens) 
# ⚡ Code
Love_films <- movielens %>%
  filter(str_detect(title, "\\bLove\\b"))
# ✅ Check
nrow(Love_films)
[1] 714

🗣 Comment: This counts matching rating rows, not distinct movies. Why can the same movie contribute more than one row?

Exact word match

Inside a quoted R pattern, write \\b to specify a word boundary.

The region column in murders contains names such as "Northeast", "North Central", and "South".

?stringr::regex

Regular expressions describe text patterns using ordinary text and special symbols. str_detect() uses them by default; regex() lets you specify matching options such as whether capitalization matters.

📜 The SYNTAX (basic): regex(pattern, ignore_case = FALSE, ...)

🎯 Goal: Match text without requiring the same capitalization.

# ⚡ Code
str_detect("HELLO", regex("hello", ignore_case = TRUE))
[1] TRUE

✅ Check: Inspect the logical result. Did the pattern match?

🗣 Comment: Here, ignore_case = TRUE allows uppercase and lowercase letters to match. This is case-insensitive matching. Use case-sensitive matching when capitalization matters to your search.

🎯 Goal: Keep rows whose region contains the whole word South.

# ⚡ Code
South_states <- murders %>%
  filter(str_detect(region, regex("\\bSouth\\b")))
# ✅ Check
nrow(South_states)
[1] 17

🗣 Comment: Word boundaries let "\\bSouth\\b" match the whole word South, but not the beginning of Southampton. The word can occur within a longer name; the entire name does not have to equal South.

🎯 Goal: Keep rows whose region contains the whole word North or South.

# ⚡ Code
NS_states <- murders %>%
  filter(str_detect(region, regex("\\b(North|South)\\b")))
# ✅ Check
nrow(NS_states)
[1] 29

🗣 Comment: Inside a pattern, | matches either alternative. This is alternation. This pattern finds the whole word North or South, so it can match North Central but not Northeast.

✔️ You used | in Chapter 10 to combine logical tests. Inside "\\b(North|South)\\b", it separates text alternatives: North or South. The OR idea is familiar, but here the symbol belongs to the quoted search pattern.

📜 The SYNTAX (basic): sapply(X, FUN, ...)

X is the list or vector to work through, and FUN is the function to apply to each element.

?sapply # sapply() applies a function to each element of a list or vector

🎯 Goal: Apply nrow() to each of the four data frames and collect the counts.

# ✅ Check

🗣 Comment: list() collects the four data frames, and sapply() applies nrow to each one. Here, it returns a vector of counts. This list is unnamed, so the resulting counts do not have the labels added above.

Build a Keyword Index

A keyword index connects each keyword with the positions of passages that match it. lapply() lets us repeat the search for each keyword and keep the results in a list.

📜 The SYNTAX (basic): lapply(X, FUN, ...)

?lapply  # lapply() applies a function to each element of a list or vector

🎯 Goal: Create the vector of keywords to search for.

# ⚡ Code
Index_Words <- c("values", "norms", "integrity", "ethics", "bias", "trust", 
                 "transparency", "responsibility", "reproducibility", "evidence", 
                 "policy", "funding", "conflict")

The searches below use case-insensitive, whole-word matching. Some words may have no matches; an empty result means the pattern was not found in the supplied text.

In function(w), w receives one keyword at a time. paste0() joins the word boundaries and keyword into a pattern. str_detect() tests each passage, and which() returns the positions of the matches. lapply() stores one result per keyword in a list.

🎯 Goal: Build the index and name each list element with its keyword.

# ⚡ Code
Index <- lapply(Index_Words, function(w) {
  which(str_detect(Science_Values, regex(paste0("\\b", w, "\\b"),
                                         ignore_case = TRUE)))
})
# ⚡ Code
names(Index) <- Index_Words

# ✅ Check
names(Index)
 [1] "values"          "norms"           "integrity"       "ethics"         
 [5] "bias"            "trust"           "transparency"    "responsibility" 
 [9] "reproducibility" "evidence"        "policy"          "funding"        
[13] "conflict"       
# ✅ Check the index for "trust".
Index[["trust"]]  
[1]  24 108 110 111 138
# ✅ Count the matching passages.
length(Index[["trust"]])
[1] 5

🗣 Comment: Index[["trust"]] contains matching passage positions. Its length counts matching passages, not individual occurrences of the word; one passage can contain it more than once.

# ⚡ Code

# ⚡ Code

trust_passages <- Science_Values[Index[["trust"]]]

✔️ In Chapter 8, which() returned positions that you used to select rows. Here, Index[["trust"]] contains matching passage positions. The brackets in Science_Values[Index[["trust"]]] use those positions to retrieve passages. Because Science_Values is a vector, there is no row-and-column comma.

🗣 Comment: Read the retrieved passages before interpreting the matches. A word can occur in a reference or notice as well as the main article; a match alone does not establish its meaning.

Summary

In this chapter, you used str_detect() to test text and produce logical results, then used those results with filter() to select rows. You refined searches with word boundaries, alternation, and capitalization options. These patterns changed what counted as a match without changing the familiar role of a logical test.

You also used sapply() to collect row counts and lapply() to build a keyword index. The index stores matching positions so you can retrieve passages with brackets. A matching-passage count does not tell you how often a word occurs or what the author means by it. Read the retrieved text to interpret the result.

Chapter Terms

Alternation: Using | inside a regular expression to allow either alternative to match.

Case-insensitive matching: Matching that ignores differences between uppercase and lowercase letters. In this chapter, ignore_case = TRUE enables it.

Case-sensitive matching: Matching that treats uppercase and lowercase letters as different.

Corpus: A collection of text prepared for analysis. Here, each entry in Science_Values is one passage.

Keyword index: In this chapter, a named list connecting each keyword with the positions of matching passages.

lapply(): Applies a function to each element of a list or vector and returns a list containing the results.

Pattern: Text or a matching rule that describes what to look for in text.

regex(): Sets regular-expression matching options, such as whether capitalization matters. It supplies a pattern to a search function; it does not perform the search itself.

Regular expression: A text pattern that can use special symbols, such as ^, \\b, and |, to describe matching rules.

sapply(): Applies a function to each element of a list or vector and simplifies the results when possible. In this chapter’s row-count example, it returns a vector of counts.

str_detect(): Tests text for a pattern and returns logical results indicating which entries match.

Word boundary: A position at the beginning or end of a word. Write \\b inside a quoted R pattern to specify one; "\\bSouth\\b" matches South but not the beginning of Southampton.
