Chapter 15: Probability functions

Simulating Outcomes with R

Overview

Probability is easier to understand when you can build and inspect examples yourself. In this chapter, you will use R to simulate random outcomes, visualize those results, and decide whether the patterns you see are reasonable. You will work with coin flips, dice rolls, bell-shaped data, and repeated simulations so that probability feels concrete rather than abstract. These are the same kinds of tools analysts use when they need to study uncertainty, test assumptions, or estimate risk.

By the end of Chapter 15 you will be able to:

  1. ⚡ Remember – Name sample(), rnorm(), and replicate().

  3. 🛠 Apply – Simulate coins, dice, and normally distributed data with R code

  4. ✅ Check – Use tables, proportions, and histograms to verify whether simulated results make sense.

  5. 🧠 Interpret – Describe sampling variability and distinguish between fair and biased outcomes using simulated evidence.

Distribution of Sums

🎯 Reading about the shape, or distribution, of data is optional, but may help you answer questions in this chapter.

Below are examples of different histogram shapes that you may encounter in real data. A histogram groups numerical values into intervals (bins); in these examples, bar heights show counts. Its shape can provide insights into the underlying distribution of the data, such as whether it is uniform, symmetric, skewed, or bimodal.

  1. Uniform: Equal-width intervals have equal probabilities, so the bars of a sample histogram should be approximately the same height.
  1. Normal: The underlying distribution is bell-shaped and symmetric. A histogram of a large random sample is usually approximately symmetric, with similar mean and median. \(Median \approx Mean\).
  1. Skewed Right: The right tail is longer than the left tail, indicating that there are a few high values that pull the mean to the right. Positive skewness. The mean is more right than the median due to extreme values. \(Median < Mean\).
  1. Skewed Left: The left tail is longer than the right tail, indicating that there are a few low values that pull the mean to the left. Negative skewness. \(Median > Mean\).
  1. Bimodal (Split Distribution): The distribution has two distinct peaks or modes. This suggests that the data might come from two different groups or processes. The mean and median may fall between the peaks, providing misleading summary statistics. Bimodal distributions often indicate hidden subpopulations.

Simulating

Probability describes how likely an event is. We can use simulation to model random outcomes and inspect the results. R provides tools for simulating random data, which allows us to explore concepts like sampling variability, distributions, and the effects of bias.

🪙 Coin Flips

In this first example, we’ll simulate flipping a coin 1,000 times and counting how many times it lands on tails. This simple experiment helps us understand the concept of a sample space, the role of randomness, and how to verify our results.

🎯 Flip 💰 1,000 fair coins (0 = heads, 1 = tails) and count tails.

Sample Space “\(S\)” is a collection (or set) of all possible outcomes in a random experiment.

Set Notation: \(S\) = {Head, Tail}

  1. 🎯 Create the data through a simulation

✔️ In Chapter 5’s discussion of required and default arguments, you learned to read a function’s inputs and recognize preset values. sample() has the default replace = FALSE, but our call supplies replace = TRUE. This is the same kind of choice you made when changing trim = 0 to trim = 0.2 in mean().

# ⚡ Test
# sample(x, size, replace = FALSE, prob = NULL)
coins <- sample(x = 0:1, size = 1000, replace = TRUE)

🗣x = 0:1 means that we are sampling from either 0 or 1. As the researcher, I decide that 0 = heads and 1 = tails. We set size = 1000 to flip the coin 1,000 times. We set replace = TRUE because we “put the coin back” each flip.

replacement means that after we sample a value, we “put it back” into the pool of possible values for the next draw. In this coin model, both outcomes remain available with the same probabilities on each flip, modeling independent events.

# ✅  Verify
unique(coins)   # values in our data set
length(coins) # total number of flips
typeof(coins)  # type of object

🗣 Coins contains 0 and 1 values where 1 represents tails of a coin flip. There are 1000 values in the integer vector.

☯️ Symmetric Data

The function rnorm() generates a vector of random numbers sampled from a normal (bell-shaped) distribution.

?rnorm  # Check the help file for rnorm()

📜 The SYNTAX: rnorm(n, mean = 0, sd = 1)

  • n is the number of random numbers to generate.

  • mean is the average value of the distribution.

  • sd is the standard deviation, controlling the spread of the distribution.

🎯 Simulate 1,000 adult female heights ~ \(N(64, 2.5^2)\) and inspect.

# ⚡ Test
heights <- rnorm(n = 1000, mean = 64, sd = 2.5)
# ✅  Verify
hist(heights,
     col    = "yellowgreen",
     main   = "Simulated Female Heights",
     xlab   = "Height (inches)")

Here we use the default bin choice from hist(). You can adjust breaks if a different choice makes the pattern easier to see.

# ✅  Verify
"Mean = "
[1] "Mean = "
mean(heights)
[1] 64.11653
"SD = "
[1] "SD = "
sd(heights)
[1] 2.508912

🗣 The histogram should look approximately bell-shaped, centered near 64 inches. Its spread should be consistent with the specified standard deviation of 2.5 inches.

Sample vs. Population Parameters: You might wonder, “Why aren’t the sample mean and standard deviation exactly 64 and 2.5?” This is because these are random samples from a normal distribution with those parameters. Each time we run the simulation, we get slightly different values due to sampling variability.

In summary, the function rnorm() generates random numbers from a normal distribution using the number of values, mean, and standard deviation you supply. The underlying distribution is symmetric, but a simulated sample need not be exactly symmetric.

🔁 Repeating Simulation

The function replicate() repeats an expression multiple times and collects the results. It can repeat simulations to estimate probabilities or study variability. It can also repeat expressions that do not generate random values.

Monte Carlo simulations use repeated random sampling to estimate probabilities or study uncertainty. They are a common use for replicate().

?replicate  # Check the help file for replicate()

📜 The SYNTAX: replicate(n, expr, simplify = "array")

  • n is the number of replications.

  • expr is the expression (a language object, usually a call) to evaluate repeatedly.

  • simplify indicates whether the result should be simplified to a vector, matrix or array if possible. The default is "array".

🎯 How variable is the number of tails in 5,000 flips? Repeat 100 times.

💰💰💰 …. 💰 That’s a lot of coin tosses!

✔️ In Chapter 6’s nesting example, you put sample() inside mean(). Here, sample() produces coin outcomes and sum() turns them into one tail count. replicate() repeats that whole calculation 100 times and collects the 100 counts. The nesting is familiar; replicate() adds repetition.

# ⚡ Test
tails_100 <- replicate(n = 100, expr = sum(sample(0:1, 5000, TRUE)))

The replicate() function:

  1. Evaluates the entire expression 100 times (because n = 100)

  2. In this example, each evaluation generates a fresh sample of 5,000 coin flips.

  3. Returns the 100 counts in a vector, which <- stores as tails_100.

# ✅  Verify
summary(tails_100)
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
   2412    2477    2499    2502    2525    2582

🗣 The minimum and maximum show the range of tail counts across these simulations. The counts vary between repetitions, and their mean should be close to 2,500, the expected number of tails in 5,000 fair coin flips.

# ✅  Verify
hist(tails_100,
     col    = "gold",
     main   = "Distribution of Tails in 5,000 Coin Flips (100 reps)",
     xlab   = "Count of Tails")

🗣 The spread shows sampling variability around the theoretical 2,500.

Normal Data with replicate()

💭 Scenario. Pretend that the university is considering making specifications grading standard practice. The provost’s office says that if thirty percent or more of students oppose this, it would trigger a halt to the proposal. We want to know the risk of the proposal being halted.

For this hypothetical example, assume student attitude scores follow a normal distribution with mean 2 and standard deviation 3. Interpret the scores on this continuous scale:

  • 0 = neutral,

  • negative values = oppose,

  • positive values = support.

We’ll first simulate a survey of 50 students. Then we simulate many 50-student samples to see how much the number of opponents could vary under this model. These are simulated attitudes, not responses collected from actual students.

Opinion Study

🎯 Generate 50 random numbers, compare each to zero, and count how many are below zero.

set.seed(1234)  # For reproducibility
# Generate 50 random numbers to represent hypothetical student attitudes
# with a normal distribution (mean = 2, sd = 3)
x <- rnorm(n = 50, mean = 2, sd = 3)
print(x)

🗣 Our model assumes an average attitude score of 2, but each simulated sample has its own mean. Negative scores represent opposition and can occur under the assumed normal distribution.

# Mark who opposes (score < 0), then count
below_zero <- x < 0
print(below_zero)

# Count how many are below zero
count <- sum(below_zero)
print(count)

🗣 We generated 50 random numbers from a normal distribution with mean 2 and standard deviation 3. We then compared each number to zero, yielding a logical vector indicating which are below zero. Finally, we summed the logical vector to count the number of values below zero.

Many Samples Simulation

Now simulate many samples from the same model to understand how the count of opponents might bounce around.

Repeat this process multiple times using replicate(). This time, let’s generate 50 random numbers in 200 iterations.

🎯 Use replicate to repeat the counts across many simulated samples.

# ⚡ Test
values_below_zero <- replicate(
  n = 200,                                     # 200 hypothetical survey runs
  expr = sum(rnorm(50, mean = 2, sd = 3) < 0)) # each run: 50 students, count opponents

Order of Operations:

  1. rnorm(n = 50, mean = 2, sd = 3) generates a sample of 50 random numbers.

  2. sum(... < 0) counts how many of those numbers are below zero.

  3. replicate(n = 200, expr = ...) repeats this process 200 times.

  4. The result is a vector of counts, one for each of the 200 samples.

# ✅  Investigate
# Useful summaries for discussion
mean(values_below_zero)   # typical number of opponents
[1] 12.77
sd(values_below_zero)     # how much the count varies
[1] 3.121831
quantile(values_below_zero, c(.1,.5,.9))  # 10th/50th/90th percentiles
10% 50% 90% 
  9  13  17

🗣 The mean is the average opponent count across the 200 simulated surveys. The standard deviation describes how much those counts vary. The 10th, 50th, and 90th percentiles summarize the lower, middle, and upper parts of the simulated counts. Your exact values can differ if you run a different sequence of random operations.

# Halt threshold: 15 out of 50 is 30%
mean(values_below_zero >= 15)  # How often do we see ≥15 opponents out of 50?
[1] 0.28

Because 15 out of 50 is 30%, the returned proportion estimates how often simulated surveys reach the halt threshold under our assumed model. It does not establish the actual level of opposition at a university.

# One-line estimate using a new set of simulated surveys:
risk_halt <- mean(replicate(200, sum(rnorm(50, 2, 3) < 0)) >= 15)
risk_halt
[1] 0.2

This one-line version generates 200 new samples rather than reusing values_below_zero, so the two estimates need not match exactly.

# Integer-aligned histogram with threshold and mean lines
threshold <- 15
max_count <- max(values_below_zero)
breaks_int <- seq(min(values_below_zero) - 0.5, max_count + 0.5, by = 1)

# ✅  Investigate
hist(values_below_zero,
     breaks = breaks_int,
     col    = "lightpink",
     main   = "Distribution of Opponents in 50-Student Surveys (200 reps)",
     xlab   = "Count of Values Below Zero")


abline(v = threshold, col = "red", lwd = 2, lty = 2) # Halt threshold
abline(v = mean(values_below_zero), col = "blue", lwd = 2, lty = 1)  # Mean line

legend("topright", 
       legend = c("Halt Threshold (15)", "Mean Count"),
       col = c("red", "blue"),
       lty = c(2, 1),
       lwd = 2,
       bg = "white",
       bty = "o")

🗣 Each bar shows how often a particular count of opponents appeared across the 200 samples. The center of the histogram is the typical count. The spread shows how much that count changes from sample to sample, even though the assumed attitude distribution stays the same. The proportion calculated above summarizes how often counts reach or exceed 15 under this model.

⚖️ Fair-Dice Check

Probability weights in sample() let you simulate biased outcomes. Recall the syntax:

📜 The SYNTAX: sample(x, size, replace = FALSE, prob = NULL)

A fair die has an equal probability of landing on each face. For a fair six-sided die, each face (1 through 6) has probability 1/6, or approximately 0.1667. The sums of two fair dice are not equally likely.

Biased Die

A biased die has unequal probabilities for its faces. For example, a biased six-sided die might have a higher probability of landing on certain faces, such as 1 and 6, while other faces (like 2, 3, 4, and 5) have lower probabilities.

The prob parameter specifies the probability weights for each element in the sampling pool.

🎯 Simulate rolling a biased die 1,000 times with specified probabilities.

# ⚡ Test
rolls <- sample(1:6, 1000, prob = c(.12,.13,.07,.23,.22,.23), replace = TRUE)

🗣 This simulates rolling one biased or “loaded” die 1000 times. The prob vector supplies one weight for each of the six possible face values in 1:6. The weights do not have to sum to 1; R rescales them to sum to 1 when needed.

# ✅  Verify that relative frequencies should be near the weights
round(prop.table(table(rolls)), 3)
rolls
    1     2     3     4     5     6 
0.130 0.133 0.076 0.222 0.223 0.216

🗣 The relative frequencies should be close to the probabilities specified in this simulation, though they will vary from run to run. This checks how the simulated results compare with the model; it does not test a physical die.

Fair vs. Unfair Dice

💭 Scenario. You are playing a dice game with a “friend” who claims their dice are fair. 🤔 Your “friend’s” dice look suspiciously unfair. We will simulate a loaded pair and a fair pair to compare their sums. This comparison illustrates possible patterns; it does not test your friend’s physical dice.

🎯 Simulate rolling two biased dice 1,000 times and compare their sums with 1,000 rolls of two fair dice.

# ⚡ Test
set.seed(8000)
biased <- c(.12, .13, .07, .23, .22, .23)  # sums to 1
friend_sum <- sample(1:6, size = 1000, replace = TRUE, prob = biased) +
  sample(1:6, size = 1000, replace = TRUE, prob = biased)
# ⚡ Test
fair_sum <- sample(1:6, 1000, TRUE) + sample(1:6, 1000, TRUE) # no 'prob' = equal chance

🗣 friend_sum and fair_sum each contain 1,000 totals. Each total is the sum of two simulated die rolls from its specified model.

🎯 Compare the distributions of sums from the biased and fair dice simulations.

# Proportions of each sum
ploaded <- prop.table(table(friend_sum))
pfair <- prop.table(table(fair_sum))
# ✅  Investigate
# Side-by-side bar plot
face_props <- rbind(Bias = ploaded, Fair = pfair)
barplot(face_props,
        beside = TRUE,
        col    = c("tomato", "steelblue"),
        main   = "Probabilities (2 Dice, 1000 rolls)",
        xlab   = "Added Face Values",
        ylab   = "Proportion")
legend("topright", legend = c("Loaded", "Fair"),
       fill = c("tomato", "steelblue"), bty = "n")

Chapter Terms

Biased Die: A die whose faces do not all have equal probabilities of occurring.

Count: The number of observations in a group or the number of times an outcome occurs. For example, the number of coin flips that land on tails.

Distribution: The pattern of possible values of a variable, together with how likely those values are or how often they occur.

Fair Die: A die whose faces have equal probabilities of occurring. Each face of a fair six-sided die has probability 1/6; the sums of two fair dice are not equally likely.

Histogram: A graph for numerical data that groups values into intervals (bins). In this chapter’s histograms, bar heights show how many observations fall in each bin.

Independent Events: Events where the occurrence of one does not change the probability of the other. In probability notation, events A and B are independent when \(P(A \cap B) = P(A)P(B)\); equivalently, knowing that one happened does not change the probability of the other.

Monte Carlo Simulation: A simulation method that uses repeated random sampling to approximate probabilities, study uncertainty, or estimate numerical results.

Normal Distribution: A continuous, bell-shaped distribution that is symmetric around its center, with most values near the mean and fewer values farther away.

Probability: A number from 0 to 1 that describes how likely an event is to occur, where 0 means impossible and 1 means certain.

Probability Weights: Numbers that control how likely each value is to be selected in a random sample. In R, the prob argument in sample() supplies these weights; they must be nonnegative, not all zero, and do not have to add up to 1.

Proportion: The count for a particular outcome divided by the total number of observations or trials. A proportion ranges from 0 to 1 and can also be expressed as a percentage.

Replacement: A sampling method where a selected value is put back before the next draw, so it can be chosen again. In R, this is controlled by replace = TRUE in functions like sample().

Reproducibility: The ability to get the same computational results again by using the same data, code, steps, and analysis conditions.

Sample Space: The set of all possible outcomes of a random experiment.

Sampling Variability: The natural sample-to-sample differences that occur because different random samples from the same population usually produce different statistics.

set.seed(): An R function that sets the starting state of the random number generator so random operations can be repeated and produce the same results again.

Simulation: A model of a random process that generates artificial outcomes so you can study what might happen and estimate probabilities or patterns.

Uniform Distribution: A distribution with equal probabilities for discrete outcomes, such as die faces, or for equal-width intervals of continuous values within its range.
