Chapter 14: Chaining

Chaining dplyr Verbs

Overview

In Chapters 11, 12, and 13, we explored several functions from dplyr (select(), filter(), mutate(), case_when(), group_by() and summarize()). You now know the key dplyr verbs one at a time. In this chapter, we’ll be putting dplyr verbs together in more complex pipelines. The real power comes from chaining them so data flows logically from raw to insight in a single readable statement.

🐱 The curiosity notes mark places to predict how a pipeline step will change the data, investigate a result with a small check, or record a side question for later.

Lesson Overview

By the end of Chapter 14 you will be able to:

  1. ⚡ Remember – List the actions of main dplyr verbs: select(), filter(), mutate(), group_by(), summarize(), arrange().

  2. 🔍 Understand – Describe how the pipe %>% passes results step‑by‑step.

  3. 🛠 Apply – Build a multi‑verb pipeline to clean and summarize data.

  4. 📊 Analyze – Inspect intermediate output to verify each step.

  5. 🧠️ Evaluate – Decide when a single pipeline is clearer than separate objects.

Keep these goals in mind as you move through each section.

🛠 Building a Pipeline

🎯 The GOAL: Find the average fuel consumption (liters/100 km) for cars in mtcars that use at least 8 L/100 km, broken down by transmission and cylinders.

Start with the data

We’ll use the built‑in mtcars dataset.

The pipe %>% passes the result on its left into the next function. Here, mtcars %>% head(2) passes mtcars to head() as its first argument, giving the same result as head(mtcars, 2).

🎯 Goal. Load mtcars and confirm shape.

data("mtcars")
# ⚡ Test:
mtcars %>%                       # rows = 32 cars, many columns
  head(2)                        # preview first two rows

head(mtcars, 2)  # base R version, same output

🗣 Data loaded correctly.

Create a new variable with mutate()

We’ll calculate fuel consumption in liters per 100 kilometers (L/100 km). The mpg column uses miles per US gallon. The formula is:

\[\frac{\text{L}}{100\text{ km}} = \frac{235.215}{\text{MPG}}\]

🎯 Goal. Add l_100km using the equation 235.215/mpg and round the value to one decimal place.

🐱 Prediction: If a car has a higher mpg value, do you expect its L/100 km value to be higher or lower? Explain why before running the code.

# ⚡ Test:
mtcars %>%
  mutate(l_100km = round(235.215 / mpg, 1)) %>%
  head(2)
# ✅ Verify:
cor(mtcars$mpg, 235.215/mtcars$mpg) < 0
[1] TRUE

🗣 The negative correlation is consistent with higher mpg and lower L/100 km. This checks the direction of the relationship, not the conversion units.

Compare this result with your prediction about the two measurements.

Keep only cars using at least 8 L/100 km

We’ll only keep cars that use at least 8 L/100 km. Use filter() to keep those rows.

🎯 Goal. Keep l_100km >= 8.

# ⚡ Test:
mtcars %>%
  mutate(l_100km = round(235.215 / mpg, 1)) %>%
  filter(l_100km >= 8) %>%
  head()

Select relevant columns

🎯 Goal. Keep cyl, am, and l_100km columns.

# ⚡ Test:
mtcars2 <- mtcars %>%
  mutate(l_100km = round(235.215 / mpg, 1)) %>%
  filter(l_100km >= 8) %>%
  select(cyl, am, l_100km)

head(mtcars2)
# ✅ Verify:
setequal(names(mtcars2), c("cyl","am","l_100km"))

🗣 Columns trimmed.

Group and summarize

Now we can group by am and cyl, then summarize to get the mean fuel consumption and count of cars in each group.

🎯 Goal. Mean l_100km and n by am, cyl.

🐱 Prediction: How many rows do you expect in the summary? Use the transmission-and-cylinder combinations in mtcars2 to explain your prediction before running the summary code.

# ⚡ Test:
mtcars_summary <- mtcars %>%
  mutate(l_100km = round(235.215 / mpg, 1)) %>%
  filter(l_100km >= 8) %>%
  select(cyl, am, l_100km) %>%
  group_by(am, cyl) %>%
  summarize(mean_l_100km = round(mean(l_100km), 2),
            n = n(), .groups = "drop")
mtcars_summary

🐱 The summary has fewer rows than mtcars2. Were more cars filtered out? I will compare the total of the group counts in n with the number of cars before the summary.

# ✅ Investigate the number of cars represented in the summary
sum(mtcars_summary$n)
nrow(mtcars2)

🗣 Both checks return 28. The six summary rows represent groups; the counts in n account for the 28 retained cars. Compare the summary’s rows with your prediction.

🗣 Explain:

Order matters in dplyr pipelines. In this pipeline, group_by() comes before summarize() so the calculations run separately for each group.

  • group_by(am, cyl) tells dplyr to treat each unique combination of am and cyl separately. group_by() divides your data into separate groups for analysis. It doesn’t change how your data looks. It adds metadata that tells subsequent functions to operate on each group separately. It’s like telling R: “For each combination of these variables, do the following…”

  • summarize() then runs mean(l_100km) per group and counts rows with n().

  • .groups = "drop" prevents grouping in the final output.

Recode transmission for readability

❓ Question: How might you check which combination of am + cyl is least fuel‑efficient?

🎯 Goal. Label am as “Automatic/Manual” in a column “Transmission” and make it a factor with level order.

# ⚡ Test: Recode transmission for readability Method 1
mtcars_summary <- mtcars_summary %>%
  mutate(Transmission = case_when(am == 0 ~ "Automatic", TRUE ~ "Manual"),
    Transmission = factor(Transmission, levels = c("Automatic","Manual"))
  )
# ✅ Verify:
is.factor(mtcars_summary$Transmission)
identical(levels(mtcars_summary$Transmission), c("Automatic","Manual"))

🗣 Labels set; order fixed.

# ⚡ Test:✔ Pipeline complete! One readable flow from raw data to insight.
mtcars_summary <- mtcars %>%
  mutate(l_100km = round(235.215 / mpg, 1)) %>%
  filter(l_100km >= 8) %>%
  select(cyl, am, l_100km) %>%
  group_by(am, cyl) %>%
  summarize(mean_l_100km = round(mean(l_100km), 2),  
            n = n(), .groups = "drop")%>%
  mutate(am = case_when(am == 0 ~ "Automatic", TRUE ~ "Manual"),
    am = factor(am, levels = c("Automatic","Manual"))
  )
mtcars_summary

Readable Result

🎯 Goal. Build one readable pipeline, then sort by the highest Mean l/100km (higher = less efficient) and keep the top row.

mtcars_summary <- mtcars %>%
  mutate(l_100km = round(235.215 / mpg, 1)) %>%
  filter(l_100km >= 8) %>%
  select(cyl, am, l_100km) %>%
  group_by(am, cyl) %>%
  summarize(mean_l_100km = round(mean(l_100km), 2),
            n = n(), .groups = "drop")%>%
  mutate(am = case_when(am == 0 ~ "Automatic", TRUE ~ "Manual"),
    am = factor(am, levels = c("Automatic","Manual"))
  ) %>%                                       # <-- close mutate() here
  arrange(desc(mean_l_100km)) %>%             # sort highest (least efficient) first
  slice(1) %>%                                # keep the single worst combo
  rename(`Mean l/100km` = mean_l_100km,       # backticks for non-syntactic name
         Count         = n,
         Cylinder      = cyl,
         Transmission  = am)

mtcars_summary

🗣 Explain: arrange() sorts the data frame by mean_l_100km (renamed Mean l/100km) in descending order, so the first row is the least fuel-efficient combination of am and cyl.

Answer the ❓ Question: Which combination of am + cyl is least fuel‑efficient?

Summary

In this chapter, you combined dplyr verbs in a pipeline to transform values, filter rows, select columns, group observations, and calculate summaries. You then labeled, sorted, and selected results to make a readable table. Each step uses the result of the preceding step, so its position in the pipeline matters.

You also predicted how a step would change the data and investigated why a grouped summary had fewer rows than its input. Inspecting intermediate results helps you explain the final table and decide where to look when a result differs from your expectation.

Chapter Terms

arrange(): A dplyr function that sorts rows using one or more columns. Use desc() to sort a column in descending order.

Grouped summary: In this chapter, a table with one row for each combination of grouping values present in the data, containing statistics such as a mean or count for that group.

Intermediate result: The data or output produced partway through a sequence of operations. Inspecting it helps you understand what a particular step changed.

Pipe: The %>% operator used here to pass a result into the next function, usually as its first argument.

Pipeline: A sequence of connected operations in which the result of one step becomes the input to the next.

Preview: A small portion of a dataset used for inspection. For example, head() returns the first six rows by default; previewing an object does not change the stored object.

rename(): A dplyr function that changes column names without changing the values in those columns.

slice(): A dplyr function that selects rows by position. In the guided pipeline, slice(1) keeps the first row after sorting.
